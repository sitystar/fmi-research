# Как самому проверить связку «FORTE ↔ модель бака»

Эта инструкция — весь маршрут проверки от начала до конца. Ничего программировать
не нужно, всё уже собрано. Время: ~5 минут.

## Что проверяем

Ваш FORTE исполняет программу «бак» (гистерезис: уровень < 4 — насос вкл, > 8 — выкл).
На другом конце TCP сидит FMITerminalBlock с математической моделью бака (Tank.fmu
из OpenModelica). Контур должен замкнуться: уровень между 4 и 8.

## Что должно быть уже установлено (однократно, уже сделано)

| Компонент | Где лежит |
|---|---|
| FMITerminalBlock (собран с патчами) | `fmi-research/build-fmitb/FMITerminalBlock` |
| Модель: готовый FMU (распакованный) | `fmi-research/models/Tank.fmu.dir/` |
| Программа «бак» для FORTE (boot-файл) | `fmi-research/app/toy/fmi_tank.fboot` |
| Скрипт запуска | `fmi-research/scripts/run_fmu.sh` |

## Шаг 1. Поднять FORTE оркестратором с программой «бак»

Загрузите проект. Требования к приложению: слушает порты **1499** и **1500**.

Проверка, что всё на месте:

```bash
ss -ltn | grep -E ':(1499|1500)'
# должно показать две строки LISTEN
```

## Шаг 2. Запустить связку

```bash
cd <каталог-репозитория>   # где лежит ИНСТРУКЦИЯ.md

# проще всего — всё автоматически:
scripts/run_fmu.sh models/Tank.fmu.dir Tank
```

Скрипт сам прочитает `modelDescription.xml` модели, возьмёт **все её входы и выходы**
и напечатает их перед запуском:

```
Входы модели  (FORTE → модель): u:0
Выходы модели (модель → FORTE): height:0
```

Опции (если нужны):
- `... Tank 60` — последний аргумент-число: остановиться через 60 секунд;
  без него — без счётчика, остановка по Ctrl-C;
- `... Tank auto auto 60` — то же явно;
- `... Tank "u:0" "height:0"` — явный список переменных вместо `auto`: нужен, только
  если подключаете не все входы/выходы или важен их порядок.

Параметры модели (A, Qin, Qout) нигде не перечисляются — они зашиты
в FMU при экспорте из средства моделирования.

Скрипт сам дождётся старта FORTE, запустит FMITerminalBlock и остановит его (по таймеру
или по Ctrl-C); FORTE не трогает. 
Если модель медленная, прикиньте длительность по физике или просто используйте режим без счётчика.

## Шаг 3. Посмотреть результат

Артефакты лягут в `runs/Tank-<время>/`:

- **`data.csv`** — trace: колонки `time;u;height`. Пустая ячейка = «в этом событии
  значение не менялось»;
- `fmitb.log` — лог FMITerminalBlock (если что-то не так — смотреть сюда).

```bash
column -t -s';' $(ls -dt runs/Tank-*/data.csv | head -1) | less
```

**Как выглядит правильная работа (проверяете глазами):**

1. `u` — столбец из единиц и нулей: длинная серия `1`, потом длинная серия `0`;
2. `height` — значения: растут на **+0.2 за строку** (0.2 с × 1 м/с), пока `u=1`;
   падает на **−0.1 за строку** (слив 0.5 м/с), пока `u=0`;
3. значения ходят в коридоре примерно **от 4 до 8.4**;
4. полный цикл (вкл→выкл→вкл) ≈ около 12–14 секунд, за 60 секунд — 4 цикла;
5. начинается так: `u=1` с первой строки, `height` растёт от 0 до 8.4 (~8 с),
   затем `u=0` и слив до 4 (~9 с), снова `u=1`...

Откуда цифры: это параметры модели (Qin=1.5, Qout=0.5, A=1) и пороги
программы (4 и 8). Совпадение trace с этими числами и есть
«логика работает правильно».

## Шаг 4 (опционально). График

Если есть gnuplot:

```bash
gnuplot -p -e 'set datafile separator ";"; unset key; set xlabel "t,с";
  plot "< tail -n +3 $(ls -dt runs/Tank-*/data.csv | head -1)" using 1:2 w l, \

```

(синяя линия — команда насоса, зелёная/вторая — уровень). Трейс также открывается
в Excel/LibreOffice или можно смотреть watch в flogic IDE во время шага 2.

## Если не работает

| Симптом | Причина и что делать |
|---|---|
| Скрипт вывел с «FORTE не слушает 1499/1500» | Приложение «бак» не загружено  или SERVER_ не в INIT. Проверить шаг 1 |
| `data.csv` пустой | Смотреть `runs/Tank-*/fmitb.log`: типичная причина — не тот FMU-каталог в аргументе |
| В `data.csv` нет колонки `u` | FORTE не шлёт данные: в приложении не подключено событие к `SERVER_1.RSP` |
| `height` не меняется | Модель не считается: `fmu.path` должен указывать на **распакованный** каталог `Tank.fmu.dir` |


## Если приходит новая модель (готовый FMU)

Подготовка FMU — не задача этого проекта: модель ведётся в Engee/OpenModelica,
оттуда экспортируется готовый `.fmu`. Чтобы подключить её:

```bash
cd <каталог-репозитория>
mkdir -p models/<Имя>.fmu.dir
unzip <путь-к-файлу>.fmu -d models/<Имя>.fmu.dir
scripts/run_fmu.sh models/<Имя>.fmu.dir <Имя>     # входы/выходы подхватятся сами
```
(то же самое — кнопкой «Импорт FMU…» в GUI). Ожидаемые цифры для проверки узнайте
у автора модели: параметры зашиты в неё при экспорте.
